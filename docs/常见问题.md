# 常见问题与排查

## 1. `unrecognized arguments: ---img`

命令行参数通常是两个横杠：

```powershell
--img 320
```

不是三个横杠。

## 2. Windows 路径被拆成多个参数

路径包含空格时必须正确引用：

```powershell
--data "C:\Data Sets\bottle\data.yaml"
```

PowerShell 脚本中优先使用 `-LiteralPath` 和 `Join-Path`。

## 3. YOLOv5 报跨盘符相对路径错误

典型错误：

```text
ValueError: path is on mount 'E:', start on mount 'C:'
```

原因通常是从 `C:` 启动位于 `E:` 的 YOLOv5。先切换工作目录：

```powershell
Set-Location 'E:\YOLO\yolov5_train\yolov5'
python train.py ...
```

## 4. CUDA 可用但训练报 `no kernel image`

`torch.cuda.is_available()` 为 `True` 不代表当前 PyTorch wheel 支持新显卡架构。检查：

```powershell
python -c "import torch; print(torch.__version__); print(torch.version.cuda); print(torch.cuda.get_arch_list())"
```

如果显卡计算能力不在构建支持列表中，应安装匹配的新版 CUDA wheel。

## 5. 训练似乎没有使用 GPU

同时检查：

```powershell
nvidia-smi
```

以及训练日志中的 `GPU_mem`。只看到系统桌面进程不能证明训练在使用 GPU。

## 6. 两个训练任务抢同一张 GPU

开始新任务前检查 Python 命令行：

```powershell
Get-CimInstance Win32_Process |
  Where-Object {
    $_.Name -match '^(python|pythonw)(\.exe)?$' -and
    $_.CommandLine -match 'train\.py|yolo.*train'
  } |
  Select-Object ProcessId, ExecutablePath, CommandLine
```

不要仅凭 PID 判断任务身份，PID 会变化。应匹配完整命令行中的训练入口和 run name。

## 7. 数据集 YAML 能打开但训练找不到图片

检查：

- `path` 是 YAML 的数据集根目录。
- `train`、`val`、`test` 是相对 `path` 的路径。
- 有些数据集使用 `valid` 目录，但 YAML 键仍叫 `val`。
- Windows YAML 路径建议使用正斜杠。

## 8. 标签数量或类别不对

检查：

- `nc` 与 `names` 数量一致。
- `class_id` 从 `0` 开始。
- 空标签表示无目标图片，而不是自动忽略图片。
- 同名图片和标签是否真的属于同一批数据。

## 9. 输出目录自动出现 `train2`、`train3`

Ultralytics 默认避免覆盖已有目录，因此会自动编号。正式实验应显式设置：

```text
project=<统一实验根目录>
name=<唯一且有意义的名称>
```

不要把自动编号目录混成同一个模型版本。

## 10. 断点续训接错权重

`resume=True` 应使用同一次实验的 `last.pt`。使用其他实验的权重可能继承错误的数据集、尺寸或优化器状态。

## 11. 文件名叫 YOLOv5，但部署后处理不工作

文件名不能证明模型结构。检查：

- 权重内部模型类。
- 网络层名称和检测头。
- ONNX 输入输出张量。
- 文件大小和 SHA-256。

经典 YOLOv5 与 YOLOv8 类模型的输出结构和后处理通常不同。

## 12. 训练是 640，导出的模型却是 320

导出命令中的 `imgsz` 决定导出输入尺寸。训练目录名或权重文件名不具有约束力。导出后用 ONNX Runtime 检查实际输入形状。

## 13. ONNX 转换报 IR 或 opset 不兼容

不要只修改模型文件里的 `ir_version`。目标工具链可能同时不支持：

- 较新的 opset。
- 新算子。
- 动态输入。
- 简化后的图结构。

应从原始 `.pt` 使用目标平台支持的参数重新导出。

## 14. K230/Hailo 编译成功但板端结果错误

继续检查：

- RGB/BGR 和数据类型。
- Letterbox 的填充位置与填充值。
- 归一化、量化范围和校准数据。
- NCHW/NHWC。
- 输出张量顺序。
- NMS 和坐标映射。

编译成功只证明模型可被工具链接受，不证明端到端检测正确。

## 15. Windows 上 `workers` 导致卡住

先使用：

```text
workers=0
```

确认训练稳定后再逐步增加。尤其要避免在没有正确入口保护的 Python 脚本中启动多进程数据加载。

## 16. 环境脚本和当前环境版本不一致

记录并比较：

```powershell
python --version
python -c "import torch, ultralytics; print(torch.__version__, ultralytics.__version__)"
pip freeze
```

“安装最新版”适合体验，不适合复现实验。正式流程应锁定经过验证的 Python、PyTorch、Ultralytics、ONNX 和 ONNX Runtime 版本。

## 17. 下载权重脚本返回 404

当前仓库尚未发布正式 GitHub Release。`download_assets.ps1` 依赖预先存在的 Release tag 和资产；在资产上传前，脚本只是发布方案，不能直接下载。

## 18. 哪些文件可以删除

不要把所有被 `.gitignore` 忽略的目录都当作缓存。训练权重、转换产物、验证 JSON 和失败日志可能是唯一证据。

清理前应先：

1. 列出精确路径。
2. 区分可重建缓存和唯一产物。
3. 核对文件大小、时间和哈希。
4. 优先移动到隔离目录，而不是直接永久删除。
