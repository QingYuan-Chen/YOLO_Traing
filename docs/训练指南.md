# YOLO 训练指南

## 1. 先确定实验定义

开始训练前记录：

- 模型代际和初始权重。
- 数据集版本、类别定义和划分。
- 输入尺寸、batch、epochs、device、workers。
- 输出目录和唯一 run name。
- Python、PyTorch、CUDA 和 Ultralytics/YOLOv5 版本。

这些信息决定实验是否可以复现。

## 2. 推荐的仓库外工作目录

默认示例：

```text
%USERPROFILE%\Desktop\YOLOTraining
├─ Datasets/
├─ Training_runs/
├─ Module_conversion/
├─ Dependencies/
└─ Config/
```

如需更换位置：

```powershell
$env:YOLO_WORKSPACE_ROOT = 'D:\YOLOTraining'
```

仓库保存代码和说明，数据、权重、训练输出和转换产物保存在工作目录。

## 3. 数据集预检

可以从 `configs/bottle.example.yaml` 复制一份配置到外部数据集目录，再修改其中的 `path`。

训练前至少检查：

1. YAML 文件存在且可以读取。
2. `train`、`val`、`test` 路径存在。
3. 图片和标签文件名能一一对应。
4. 类别编号从 `0` 开始且小于 `nc`。
5. 坐标为合法归一化数值。
6. 训练集与验证集没有明显重复或泄漏。
7. 类别数量、样本量和缺失标签数量已记录。

## 4. Ultralytics 新版 YOLO

### 4.1 环境确认

```powershell
conda activate yolo
python -c "import torch, ultralytics; print(torch.__version__); print(ultralytics.__version__); print(torch.cuda.is_available())"
nvidia-smi
```

`torch.cuda.is_available()` 为 `True` 只说明 CUDA 可见。仍应通过最小张量计算或训练日志确认当前 PyTorch 构建支持显卡计算能力。

### 4.2 已验证的 YOLOv8n 入口

```powershell
powershell -ExecutionPolicy Bypass -File .\start_yolov8n_640.ps1
```

脚本默认使用仓库外塑料瓶数据集，并把结果写入：

```text
Training_runs/bottle/yolov8n_640
```

启动新训练前应确认该 run name 没有被其他进程使用，也不要让两个训练任务同时占用同一张 GPU。

### 4.3 通用 PowerShell 示例

```powershell
powershell -ExecutionPolicy Bypass -File .\yolo_new\Powershell\train_yolo_new.ps1
```

该脚本保留为可修改的教学示例。训练参数和 run name 应与正式实验区分。

### 4.4 Python API

```powershell
& 'E:\Anaconda_envs\envs\yolo\python.exe' .\yolo_new\Python\train.py
```

Python 示例集中使用 `yolo_new/Python/project_paths.py` 解析仓库和工作目录。

## 5. 经典 YOLOv5

### 5.1 上游源码

仓库不提交完整的 `ultralytics/yolov5` 源码。使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\yolov5_train\setup_yolov5_env.ps1
```

初始化脚本应锁定经过验证的上游提交。不要在整理仓库或复现实验时顺手拉取最新 `master`。

### 5.2 开始训练

```powershell
powershell -ExecutionPolicy Bypass -File .\yolov5_train\train_yolov5.ps1
```

默认示例输出：

```text
Training_runs/bottle/yolov5n_classic_320
```

在 Windows 中，应先切换到 `E:\YOLO\yolov5_train\yolov5` 再运行 `train.py`，避免 Python 在不同盘符之间计算相对路径时报错。

## 6. 验证与预测

验证的目标是回答“这个权重在指定数据集和协议上表现如何”。至少记录：

- 权重 SHA-256。
- 数据 YAML 和数据集版本。
- `imgsz`、split、batch、device。
- Precision、Recall、mAP50、mAP50-95。

预测适合做肉眼检查，但不能代替正式验证。重点观察：

- 漏检和误检。
- 边缘、遮挡、小目标、强反光和低照度场景。
- 类别标签是否正确。
- Letterbox、颜色空间和输入尺寸是否一致。

## 7. 断点续训

断点续训通常使用 `last.pt`：

```powershell
powershell -ExecutionPolicy Bypass -File .\yolo_new\Powershell\resume_yolo_new.ps1
```

注意：

- `resume=True` 会继承原训练配置。
- 不要把另一个实验的 `last.pt` 当成当前实验。
- 先确认输出目录和日志，不要覆盖已有证据。

## 8. 导出模型

新版 Ultralytics：

```powershell
.\Model_Conversion\export_pt_to_onnx.ps1 `
  -ModelPath '...\best.pt' `
  -OutputPath '...\model.onnx' `
  -ImageSize 640 `
  -Opset 17 `
  -Simplify
```

经典 YOLOv5：

```powershell
.\Model_Conversion\export_yolov5_pt_to_onnx.ps1 `
  -ModelPath '...\best.pt' `
  -OutputPath '...\model.onnx' `
  -ImageSize 320 `
  -Opset 12
```

导出完成后至少使用 `onnx.checker` 和 ONNX Runtime 创建会话验证模型，再进入 K230 或 Hailo 转换。

## 9. 训练完成的最低证据

不能只因为进程启动就声称训练成功。最低证据包括：

- 启动日志无立即报错。
- 指定 Python/YOLO 进程存在。
- GPU 进程和显存占用符合预期。
- `results.csv` 有表头和至少一个完整 epoch。
- 最终 run 目录包含完整指标和权重。

如果训练被中止，应如实标记为中止，不把部分输出称为完成模型。
