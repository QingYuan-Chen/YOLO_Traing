# YOLO 基础

## 1. YOLO 解决什么问题

YOLO 是一类单阶段视觉模型。目标检测任务中，模型一次前向推理通常同时给出：

- 目标框位置。
- 目标存在的置信度。
- 目标类别概率或类别分数。

训练阶段让模型学习图片与标注之间的关系；推理阶段只需要图片和训练好的权重。

## 2. 目标检测数据的基本组成

一套常见的 YOLO 数据集包含：

```text
dataset/
├─ train/
│  ├─ images/
│  └─ labels/
├─ valid/
│  ├─ images/
│  └─ labels/
└─ test/
   ├─ images/
   └─ labels/
```

每张图片对应一个同名 `.txt` 标签文件。检测标签的一行通常是：

```text
class_id x_center y_center width height
```

后四个数通常是相对图片宽高归一化后的数值，范围应在 `0~1`。

## 3. 权重、配置和训练结果

这三类文件容易混淆：

| 类型 | 示例 | 作用 |
|---|---|---|
| 预训练权重 | `yolov8n.pt` | 训练起点，可以缩短收敛时间 |
| 数据集配置 | `data.yaml` | 告诉训练器图片位置和类别定义 |
| 训练结果 | `best.pt`、`last.pt` | 当前任务训练得到的模型 |

`best.pt` 通常是验证指标最好的权重，`last.pt` 是最后一个 epoch 保存的权重。断点续训通常使用 `last.pt`，最终验证和部署通常优先评估 `best.pt`。

## 4. 经典 YOLOv5 与新版 Ultralytics YOLO

经典 YOLOv5 通常具有这些特征：

- 使用 `ultralytics/yolov5` 独立仓库。
- 入口是 `train.py`、`val.py`、`detect.py`、`export.py`。
- 常见网络结构包含 `C3`、`SPPF`、anchors 和经典 `Detect`。
- 常见部署链按 anchor-based 输出处理。

YOLOv8、YOLO11、YOLO12、YOLO26 等新版模型通常：

- 使用 `ultralytics` Python 包。
- 通过 `yolo` CLI 或 `from ultralytics import YOLO` 调用。
- 检测头和后处理可能与经典 YOLOv5 完全不同。
- 不能直接复用经典 YOLOv5 的板端后处理。

模型名称是提示，不是身份证明。一个叫 `YOLOV5.pt` 的文件仍可能包含新版检测头。需要结合模型元数据、结构、输入输出和哈希判断。

## 5. 模型尺寸

同一代模型常见 `n`、`s`、`m`、`l`、`x` 等尺寸：

```text
n → 参数少、速度快、精度上限较低
s → 小型
m → 中型
l → 大型
x → 最大、显存和算力需求最高
```

边缘设备通常先从 `n` 或 `s` 开始。训练阶段能跑的大模型，不一定适合 K230、Hailo-8L 或其他板端设备。

## 6. 输入尺寸

常用输入尺寸有 `320`、`640`、`1280`。尺寸越大：

- 小目标可能更容易检测。
- 显存占用和训练时间通常增加。
- 导出和板端推理成本也会增加。

训练、验证、导出和部署必须明确各自使用的输入尺寸。文件名中写了 `640`，不能代替实际检查模型输入张量。

## 7. 常见训练指标

| 指标 | 含义 |
|---|---|
| Precision | 预测为目标的结果中有多少是正确的 |
| Recall | 真实目标中有多少被检测出来 |
| mAP@0.5 | IoU 阈值 0.5 下的平均精度 |
| mAP@0.5:0.95 | 多个 IoU 阈值上的平均精度，更严格 |

比较模型时必须使用相同的数据集划分、输入尺寸、置信度设置和评估协议。不同验证集上的 mAP 不能直接比较。

## 8. 从训练到部署

典型链路为：

```text
数据集
  → PyTorch 训练
  → best.pt
  → ONNX
  → 目标平台编译或量化
  → 板端模型
  → 匹配的预处理和后处理
```

每一步都是独立的验证关口。上一步成功不代表下一步自动成功。
